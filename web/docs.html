技术架构Technical architecture

这是德威送给胡佳的一份礼物：把写过的卡片、做过的网页、一起住过的家和走过的地方，放在一个可以慢慢翻看的地方。访客只看到入口和两张精选风景照片；其余回忆都需要用 Microsoft 账号登录。

A gift from Dewei to Hujia: a place to revisit the cards, the first website, the homes and the places we have shared. Visitors see only the entrance and two selected scenery photos; every other memory needs a Microsoft sign-in.

保存和上传Saving and uploading

  • 每次保存都带上版本号；DynamoDB 只在版本没变时写入，所以两台设备同时编辑也不会互相覆盖。没保存成功的文字留在浏览器里。
  • 上传时 Lambda 先记下文件大小和类型，再给浏览器一个 15 分钟有效、只能上传这个大小和类型的签名链接。文件先进入 pending/，检查通过后才复制到回忆里；没完成的上传一天后自动清理。照片和视频保留原件，不压缩、不转码。
  • 回忆册、相簿和旧网页这些私人页面由 Lambda 在登录后返回，内容存放在私有存储桶里，不在公开代码里。
  • Every save carries a version number; DynamoDB writes only if the version is unchanged, so two devices editing at once never overwrite each other. Unsaved text stays in the browser.
  • For an upload the Lambda first records the file's size and type, then gives the browser a 15-minute link that can upload only that size and type. Files land in pending/ and are copied into the memory only after the check; unfinished uploads are removed after a day. Photos and videos are kept as originals, never resized or re-encoded.
  • The private pages (memory book, album, old website) are returned by the Lambda after sign-in. Their content lives in the private bucket, not in the public code.

The Lambda concurrency limit caps the app itself at about US$2 an hour; CloudFront traffic has no hard cap. There is no jh-specific budget alert yet; adding one (and a WAF rate limit) is an owner's decision, listed under accepted risks on the Security tab.

安全与隐私Security and privacy

访客只看到入口和两张审核过的风景照片。回忆页面、照片、视频和证件材料都需要先登录；可以登录的账号由 Microsoft 端管理。私人媒体存放在独立的私有 S3 存储桶，链接只在登录后签发，5 分钟后失效。

Visitors see the entrance and two reviewed scenery photos. Memories, photos, videos and documents require sign-in, and eligible accounts are managed on the Microsoft side. Private media lives in a separate private S3 bucket; its links are issued only after sign-in and expire after 5 minutes.

威胁模型Threat model

下面的表格以英文记录（2026 年 11 月复审）。

Reviewed November 2026.

Assets

  • Private media: original photos and videos, the redacted licence, the letter and the gift pages (S3 private bucket).
  • Memory text: captions, notes and wishes (DynamoDB).
  • The Microsoft app secret (SSM, /hujia/). It also derives the cookie-signing keys, so whoever holds it can mint sessions. The tenant ID is not secret (it appears in the sign-in URL) and is shared by every dliu.com app in /dliu/entra-tenant-id; the Lambda can read only that one shared parameter.
  • Session cookies in our browsers.
  • The AWS bill and account, shared with the other dliu.com sites.
  • Site integrity: the public code bucket and CloudFront.

Trust boundaries and data flows

  1. Browser → CloudFront (internet, TLS 1.2+). Everything from the browser is untrusted.
  2. CloudFront → S3 site (origin access control; the bucket blocks all other access).
  3. CloudFront → private bucket, only for the two scenery objects (origin access control + key-scoped bucket policy).
  4. CloudFront → Lambda function URL (origin access control; the URL needs AWS IAM signatures, so it cannot be called directly).
  5. Browser ↔ Microsoft Entra ↔ Lambda: authorization code + PKCE; the Lambda redeems the code with the secret.
  6. Lambda → DynamoDB, S3, SSM (IAM role, least privilege).
  7. Browser → private bucket directly, with presigned links: GET for 5 minutes, PUT for 15 minutes (fixed size and type).
  8. Developer → AWS (named IAM user, root refused by the scripts) and → GitHub (public repo, no secrets; CI has a read-only token and no AWS credentials).

What was checked

  • Input validation: path IDs are limited to [A-Za-z0-9-] and 60–80 characters; dates, booleans, text lengths, upload types (no HTML, SVG or PDF uploads) and sizes are checked before any write; request bodies are JSON objects of at most 96 KB.
  • Authorization on every path: only /api/me, /api/public, /api/guest/*, /auth/* and the public code work without a session. test/api.test.js checks that every private path refuses anonymous reads without touching storage.
  • Error handling: unexpected errors return a fixed message; logs keep the path and the error message, never request bodies, tokens or secrets.
  • Secrets: none in code, logs or Git history (gitleaks git --log-opts=--all: no leaks in 51 commits). Personal photos, documents and research are excluded from Git.
  • AWS settings: both buckets block public access and require TLS; the private bucket is versioned with owner-enforced objects; the Lambda URL needs IAM signatures; every log group keeps logs for 90 days, including the CDK helper Lambdas' (those groups are created by Lambda, not by the stack, so a deploy cannot change them); DynamoDB has point-in-time recovery and deletion protection.
  • Tests: every fix above has a regression test (test/routes.test.js, test/stack.test.js, test/api.test.js).

剩余风险Accepted residual risks

  • CloudFront 流量费用没有硬上限；目前没有针对 jh 的预算提醒（JH-07，待我们决定）。
  • 匿名请求可以占满 Lambda 的 10 个并发，短时间内影响我们使用（JH-09）。
  • 会话 30 天有效，不能单独撤销；轮换 Microsoft 密钥会让所有会话失效（JH-08）。
  • 登录由 Microsoft Entra 把关：应用只属于我们自己的组织，必须被分配才能登录。之后网站的 isAllowed 只检查是不是本组织的 @dliu.com 账号，网站里没有逐人的名单。谁能进来由 Entra 的分配决定（JH-16）。
  • 我们两人都能编辑全部内容，这是设计如此。
  • 私人礼物页面使用内联脚本（'unsafe-inline'），因为它们是我们自己写的内容；从 API 读到的文字只会作为纯文本显示。
  • CloudFront traffic cost has no hard cap, and no jh budget alert exists yet (JH-07, owner's decision).
  • Anonymous requests can fill the Lambda's 10 slots and briefly lock us out (JH-09).
  • Sessions last 30 days and cannot be revoked individually; rotating the Microsoft secret ends them all (JH-08).
  • Microsoft Entra is the sign-in gate: the app is single-tenant with user assignment required. After that, isAllowed accepts any @dliu.com account from the tenant, with no per-person list in the app; Entra assignment decides who gets in (JH-16).
  • Both of us can edit everything, by design.
  • The private gift pages use inline scripts ('unsafe-inline') because they are our own content; text read from the API is shown only as plain text.

/health: format, caching and what each check reads

GET https://jh.dliu.com/health (HEAD also works). No cookies, Authorization header or query string reach the Lambda, which answers before reading any request data. Cached 60 s at CloudFront (Cache-Control: public, max-age=60). Content-Type: application/health+json; HTTP 200 for pass or warn, 503 for fail. Each check has a 4 s timeout and is warn/slow after 2.5 s. output is only slow, timeout or read failed.
